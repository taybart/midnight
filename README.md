# midnight

Midnight is a Lua dialect that runs on Go: run Midnight (and Lua) scripts in Go
programs, or compile Midnight to Lua. Source files use `.mn` (or `.midnight`).

Midnight started as a fork of [Erde](https://erde-lang.github.io/) and is
implemented as a fork of [gopher-lua](https://github.com/yuin/gopher-lua) (a
Lua 5.1 VM written in Go) with a Midnight parser. Midnight is parsed directly
into gopher-lua's AST, which then goes through gopher-lua's unchanged compiler
and VM. There is no intermediate Lua source and no dependency on the Erde (Lua)
reference compiler.

```
            Lua source ──> parse.Parse ─────────┐
                                                ├──> AST ──> Compile ──> VM
       Midnight source ──> parse.ParseMidnight ─┘     │
                                                      └──> luagen ──> Lua source
```

## Installation

```sh
go get github.com/taybart/midnight
go install github.com/taybart/midnight/cmd/midnight@latest # CLI
```

## CLI

```sh
midnight script.mn          # run a script (*.lua scripts run as Lua)
midnight -c script.mn       # print the script compiled to Lua
midnight compile .          # compile all *.mn files under . (foo.mn -> foo.lua)
midnight compile src -o out # ... into out/
midnight clean .            # remove Lua files generated by `midnight compile`
midnight lint .             # check *.mn files for likely mistakes
midnight fmt .              # format *.mn files in place
midnight -e 'print("{1 + 1}")'
midnight                    # REPL
cat script.mn | midnight -  # stdin (also works w/ `midnight <(...)`)
```

Scripts that don't end in `.lua` are treated as Midnight (use `-lang lua` or
`-lang midnight` to override). See `midnight -h` for all options.

See [docs/TOOLS.md](docs/TOOLS.md) for `compile`, `clean`, `lint`, and `fmt`:
what they do, their rules, and their output formats / exit codes (for editor
integrations and CI).

## Language additions

Besides Erde's syntax, Midnight has `match` statements, `if` / `match`
expressions, interpolation formats, and markup elements.
Scripts that use them only run on midnight (or as `midnight -c` output).

### `match`

Rust style `match` statements:

```midnight
match mode {
  "movie" => { ... }
  "show" | "series" => { ... }   -- any of
  _ if count > 5 => { ... }      -- guard
  _ => { ... }                   -- anything else (must be last)
}
```

This compiles to an `if` / `elseif` / `else` chain:

```lua
do
  local subject = mode
  if subject == "movie" then ...
  elseif subject == "show" or subject == "series" then ...
  elseif count > 5 then ...
  else ... end
end
```

- The subject is evaluated once. There is no fallthrough.
- Patterns are any expression compared w/ `==`. Names are values (ex. a
  constant like `MOVIE =>`), not bindings.
- `|` separates patterns, so a bitwise or in a pattern needs parentheses
  (`(a | b) =>`).
- `pattern if guard =>` also requires `guard`.
- `break` and `continue` in an arm apply to the enclosing loop.
- `match` is a contextual keyword, so existing code that uses it as a name
  keeps working (`s:match(p)`, `string.match`, `t.match`, `local match = 1`).
  At the start of a statement, `match` followed by `=`, `,`, `.`, `[`, `:`, an
  assignment operator, or a call (`match(x)`) is still a name; `match (x) {` is
  a match statement.
- Where an expression is expected, it's a [match expression](#if--match-expressions).

### `if` / `match` expressions

Where an expression is expected, `if` and `match` have a value: the value of
the branch that's taken.

```midnight
local label = if user.admin { user.title } else { 'member' }

local icon = match entry.kind {
  "dir" => { "📁" }
  "link" | "submodule" => { "🔗" }
  _ => { "📄" }
}

<nav>{if c.current { c.name } else { <a href="/{c.path}">{c.name}</a> }}</nav>
```

Unlike `cond && a || b`, the branch taken is the value even when it's `nil`
or `false` (`if admin { title } else { 'member' }` is `title`, nil or not).

- Each branch is one expression, truncated to one value (like parentheses).
  For statements, use an `if` / `match` statement.
- The fallback is required (`else`, `_ =>`), so a missing case is never a
  silent `nil`. `elseif` chains, and `match` patterns, `|`, and guards are the
  same as the statements'.
- As the (first) value of a declaration or assignment, or of a `return`
  (including an arrow function's expression body), they compile to an if
  chain, at no cost:

  ```lua
  -- local label = if user.admin { user.title } else { 'member' }
  local tmp
  if user.admin then tmp = user.title else tmp = "member" end
  local label = tmp
  ```

  Anywhere else (ex. an argument, a table field, a markup child), the if
  chain is in a function that's called right away, which allocates a closure
  each time it runs. In a hot loop, prefer a local:
  `local label = if ... ; f(label)`.
- At the start of a statement, `if` / `match` are still statements.
- `match` is still a name where it can be one: it's a match expression only
  when its subject starts on the same line and is followed by `{` and an arm
  (`... =>`). So `match - 1` and `local y = match` are names; a unary subject
  needs parentheses (`match (-x) { ... }`).

### Interpolation formats

`{expr:%spec}` formats an interpolated value w/ `string.format`:

```midnight
print("progress {done / total * 100:%.1f}%")  -- progress 42.0%
print("id {id:%08x}, {name:%-10s}|")
```

compiles to

```lua
print(string.format("%.1f", done / total * 100) .. "%")
```

- The spec is one `string.format` directive: flags, width, precision, and a
  conversion (`c d i o x X e E f g G q s`).
- Only formatted parts call `string.format`; the rest are still
  `tostring(x)` joined w/ `..`.
- `:` must be directly followed by `%`. A method name can't start w/ `%`,
  so `{obj:method()}` is still a method call.
- Works in double quoted and block strings (which interpolate), not single
  quoted ones. `\{` escapes the brace as usual.

### `markup`

JSX style elements, and a runtime (`midnight.markup`, preloaded) that renders them to
HTML, w/ components, per component state, scoped styles, and interactive pages
(w/ a host like [rest](https://github.com/taybart/rest)'s `page` handlers):

```midnight
local Card = (props) -> <section class="card">
  <h2>{props.title}</h2>
  {props.children}
</section>

print(require('midnight.markup').render(<Card title="hi"><p>hello {name}</p></Card>))
```

Elements are lowered to `h(tag, props, ...children)` calls (`h` is imported
automatically if it isn't in scope, or `-markup-factory name` uses another function), so
the compiled output runs on any lua w/ the runtime. See
[docs/MARKUP.md](docs/MARKUP.md).

## Go API

The package name is `lua`, since it is still a Lua VM. Everything from
gopher-lua works the same way (see [docs/gopher-lua.md](docs/gopher-lua.md)),
plus:

```go
import lua "github.com/taybart/midnight"

L := lua.NewState()
defer L.Close()

// Midnight equivalents of Load / LoadString / DoString
L.DoMidnightString(`print("hello {_VERSION}")`)
fn, err := L.LoadMidnightString(source)
fn, err := L.LoadMidnight(reader, "name.mn")

// *.mn files load as Midnight, and `require` finds `?.mn` modules
L.DoFile("script.mn")
```

Midnight and Lua modules can `require` each other freely, since both compile to the
same bytecode.

Lower level:

```go
import (
	"github.com/taybart/midnight/luagen"
	"github.com/taybart/midnight/parse"
)

chunk, err := parse.ParseMidnight(reader, "name.mn") // []ast.Stmt, same as parse.Parse
proto, err := lua.Compile(chunk, "name.mn")
source := luagen.Generate(chunk) // Lua source (works for any chunk, including from Lua)
```

## Differences from Erde

Apart from the [language additions](#language-additions), midnight accepts
the language of the [Erde reference compiler](https://github.com/erde-lang/erde)
and is tested against its spec suite (see [Testing](#testing)). Other
differences:

- **No Lua targets.** gopher-lua is Lua 5.1 + `goto`, so there are no
  target-specific restrictions (ex. `goto` is always allowed, `break` doesn't
  have to be the last statement in a block).
- **Bit operators** (`|`, `~`, `&`, `<<`, `>>`, unary `~`) compile to calls
  into a `bit32` library (Lua 5.1 has no bit operators), which midnight adds to
  the standard libraries.
- **Error line numbers** refer to the Midnight source directly (no source maps or
  error rewriting needed).
- **Compound assignment evaluates index chains once.** `t[f()] += 1` calls `f`
  once (the reference compiler calls it twice).
- **Lua keywords as names.** Midnight allows names like `end` that are keywords in
  Lua. midnight uses them as is; the reference compiler renames them (`end_`),
  which is only visible for globals.

### luagen output

`midnight -c` / `luagen.Generate` output is valid Lua 5.1+ (and LuaJIT), except:

- `continue` and `goto` compile to `goto`, which needs Lua 5.2+ or LuaJIT.
- Bit operators compile to `bit32` calls, which need a `bit32` library (builtin
  in Lua 5.2, otherwise use a polyfill).

Statements are kept on their original lines, so errors in the generated Lua
report the Midnight line numbers. Comments are not preserved.

## Testing

```sh
go test ./...
```

Besides gopher-lua's own tests, this runs:

- **Midnight spec tests** ([midnight_spec_test.go](midnight_spec_test.go)): every snippet
  from the reference compiler's spec suite, run three ways (reference compiler
  output, parsed natively, compiled w/ luagen), which must all give the same
  results. Snippets the reference compiler rejects must be rejected. Regenerate
  [testdata/midnight-spec](testdata/midnight-spec) w/
  `_tools/midnight-spec/update.sh <erde-lang/erde checkout>`.
- **luagen round trips** ([luagen_test.go](luagen_test.go)): gopher-lua's Lua
  test scripts, run after Lua -> AST -> Lua.

`_tools/midnight-spec/selfhost.sh <erde-lang/erde checkout>` compiles the reference compiler
(written in Midnight) to Lua w/ midnight, and checks that the result compiles its own
sources byte-for-byte the same as the reference compiler.
